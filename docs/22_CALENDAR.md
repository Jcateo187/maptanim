## 📌 Overview
The **Calendar Screen** corresponds to the `📅 Calendar` tab in the bottom navigation bar and operates as an integrated view within the **Monitoring Dashboard System** (`MonitoringDashboardOverlay.kt`). It maps all active farming activities, scheduled tasks, pest alert windows, and harvest milestones on a monthly timeline. 

All calendar events are dynamically generated by the **DSS Engine** (`DssEngine`, `GrowthStageCalculator`) when monitoring is initiated for a crop plot. All data is persisted in **Room DB** and synchronized with **Supabase PostgREST** — no hardcoded dates or static task fallbacks are used.

---

## 🔹 Data Sources & Schema Mapping

| Data Element | Source Table / Class | Updated By | Description |
|---|---|---|---|
| Scheduled Tasks | `tasks` table (Room → Supabase) | `DssEngine.kt` rule engine | Dynamic tasks (💧 Water, 🌿 Fertilize, 🐛 Pest Alert) |
| Completed Activities | `activities` table (Room → Supabase) | Farmer manual logging | Logged farming actions with timestamps and amounts |
| Harvest Records | `harvest_records` table (Room → Supabase) | Farmer harvest confirmation | Production yield (kg/units) and quality rating |
| Starting / Planting Date | `crop_plots.planted_date` (Room DB) | Farmer Starting Date Selection | Simulation baseline date for growth stage tracking |
| Harvest Milestones | Derived: `planted_date + days_to_harvest` | `GrowthStageCalculator.kt` | Projected target harvest date for active plots |

> ⚠️ **No static date lists.** Calendar entries dynamically recalculate whenever a plot's monitoring simulation starts, updates, or cancels.

## 🔹 Monitoring Simulation Controls (Start & Cancel)

Inside the **Monitoring Hub / My Plants Panel**, each crop plot features interactive simulation controls that directly drive the Calendar schedule:

```
                      [ CROP PLOT SELECTION ]
                                 │
                 ┌───────────────┴───────────────┐
                 │                               │
                 ▼                               ▼
       [ START MONITORING ]             [ CANCEL MONITORING ]
                 │                               │
   1. Select Starting Date              1. Reset `is_active` / `planted_date`
   2. Persist `crop_plots.planted_date` 2. Clear projected DSS tasks
   3. Trigger `DssEngine` calculation   3. Remove dots from Calendar View
   4. Populate Calendar Timeline         
```

### 1. Starting Date Simulation Setup
* **Trigger**: Tapping **"📅 Start Monitoring"** on an unmonitored crop plot (indicated by a floating `📅` badge on the 2D canvas).
* **Starting Date Input**: The farmer selects the starting date (defaults to `LocalDate.now()`).
* **DSS Initialization**:
  - `crop_plots.planted_date` is updated in Room SQLite and queued for Supabase sync.
  - `GrowthStageCalculator` computes current growth stage (`GERMINATION`, `EARLY_VEGETATIVE`, `MID_VEGETATIVE`, `FLOWERING`, `FRUITING`, `HARVEST_READY`).
  - `DssEngine` projects watering intervals, NPK fertilization dates, and seasonal pest alert risk windows directly onto the monthly calendar grid.

### 2. Cancel Monitoring Action
* **Trigger**: Tapping **"❌ Cancel Monitoring"** or resetting a plot in the Monitoring Hub.
* **Effect**:
  - Sets `crop_plots.planted_date = null`.
  - Automatically cancels and purges uncompleted projected tasks associated with `plot_id` from the `tasks` table.
  - Immediately updates the Calendar grid via `StateFlow` — removing event dots and projected harvest milestones for that plot.

## 🔹 Calendar Views

### Monthly View
- Standard monthly grid (7 columns, 4–6 rows).
- Color-coded event dots on each date cell:
  - 💧 **Blue dot** = Water task(s) on that day
  - 🌿 **Green dot** = Fertilize task(s) on that day
  - 🌾 **Amber dot** = Target Harvest milestone
  - 🐛 **Red dot** = Pest & disease alert window
- Tapping any date cell expands that day's detailed task list below the calendar.

### Day Detail List (below calendar on date tap)
Mirrors the TODAY'S TASKS panel:
```
[💧] Water PLOT 3            Tomato         >
[🌿] Fertilize Eggplant      PLOT 1         >
[🌾] Harvest Ready Milestone PLOT R         >
```

## 🔹 CalendarViewModel Architecture

```kotlin
@HiltViewModel
class CalendarViewModel @Inject constructor(
    private val taskRepository: TaskRepository,
    private val harvestRepository: HarvestRecordRepository,
    private val cropPlotRepository: CropPlotRepository,
    private val cropRepository: CropRepository,
    private val dssEngine: DssEngine
) : ViewModel() {

    private val _selectedDate = MutableStateFlow(LocalDate.now())
    val selectedDate: StateFlow<LocalDate> = _selectedDate.asStateFlow()

    private val _selectedMonth = MutableStateFlow(YearMonth.now())
    val selectedMonth: StateFlow<YearMonth> = _selectedMonth.asStateFlow()

    // Tasks for the selected month — observed live from Room DB
    val monthTasks: StateFlow<Map<LocalDate, List<FarmTask>>> = combine(
        _selectedMonth,
        taskRepository.observeAllTasks(farmerId = "")
    ) { month, tasks ->
        tasks
            .filter { YearMonth.from(LocalDate.parse(it.dueDate)) == month }
            .groupBy { LocalDate.parse(it.dueDate) }
    }.stateIn(viewModelScope, SharingStarted.WhileSubscribed(5000), emptyMap())

    // Tasks for the selected day
    val selectedDayTasks: StateFlow<List<FarmTask>> = combine(
        _selectedDate, monthTasks
    ) { date, tasks ->
        tasks[date] ?: emptyList()
    }.stateIn(viewModelScope, SharingStarted.WhileSubscribed(5000), emptyList())

    // Harvest milestones — calculated from crop_plots.planted_date + crops.days_to_harvest
    val harvestMilestones: StateFlow<Map<LocalDate, List<HarvestMilestone>>> =
        cropPlotRepository.observeAllPlotsWithCrop(farmerId = "")
            .map { plots ->
                plots.mapNotNull { plot ->
                    val plantedDateStr = plot.plantedDate ?: return@mapNotNull null
                    val plantedDate = LocalDate.parse(plantedDateStr.take(10))
                    val daysToHarvest = plot.cropId?.let { cropRepository.getCropById(it)?.daysToHarvest } ?: 60
                    val harvestDate = plantedDate.plusDays(daysToHarvest.toLong())
                    harvestDate to HarvestMilestone(
                        plotLabel = plot.plotLabel,
                        cropName = plot.cropName ?: "",
                        harvestDate = harvestDate
                    )
                }.groupBy({ it.first }, { it.second })
            }
            .stateIn(viewModelScope, SharingStarted.WhileSubscribed(5000), emptyMap())

    // Start simulation for a plot with custom starting date
    fun startMonitoring(plotId: String, startingDate: LocalDate) {
        viewModelScope.launch {
            cropPlotRepository.updatePlantedDate(plotId, startingDate.toString())
            dssEngine.generateTasksForPlot(plotId, startingDate)
        }
    }

    // Cancel simulation for a plot
    fun cancelMonitoring(plotId: String) {
        viewModelScope.launch {
            cropPlotRepository.updatePlantedDate(plotId, null)
            taskRepository.cancelTasksForPlot(plotId)
        }
    }

    fun selectDate(date: LocalDate) { _selectedDate.value = date }
    fun nextMonth() { _selectedMonth.value = _selectedMonth.value.plusMonths(1) }
    fun previousMonth() { _selectedMonth.value = _selectedMonth.value.minusMonths(1) }
}
```

## 🔹 TaskDao Queries (Room SQLite)

```kotlin
@Dao
interface TaskDao {
    @Query("""
        SELECT t.* FROM tasks t
        INNER JOIN farms f ON t.farm_id = f.id
        WHERE f.farmer_id = :farmerId
        ORDER BY t.due_date ASC
    """)
    fun observeAllTasks(farmerId: String): Flow<List<TaskEntity>>

    @Query("DELETE FROM tasks WHERE plot_id = :plotId AND is_completed = 0")
    suspend fun cancelUncompletedTasksForPlot(plotId: String)
}
```

## 🔹 Activity Logging & Live Flow Sync

When a farmer completes a task:
1. `TaskEntity.is_completed` is marked `true` in Room DB.
2. An `ActivityEntity` is logged with `performed_at = Instant.now().toString()`.
3. Changes queue in `SyncQueueEntity` for background Supabase synchronization.
4. `StateFlow` automatically emits the updated state, refreshing the Calendar UI without manual reloads.
